\section*{提案摘要}
\addcontentsline{toc}{section}{提案摘要}

\subsection*{问题}

漫展、晚会、典礼这种现场演出基本都跑 PowerPoint。但 PPT 的常规操作方式在舞台上其实并不靠得住:

\begin{itemize}
  \item 翻页器靠 USB / 蓝牙,后台和舞台中间隔层布幕,信号一打折就掉。
  \item 主持人在台前,PPT 跑在后台机器上。每次"下一页"靠喊话或对讲机,反应总慢半拍。
  \item 漫展常用的内嵌答题、抽奖、票选,要触发 PPT 里的 VBA 宏 —— 翻页器干不了这事,得有专人守鼠标。
  \item 节目出岔子要瞬间黑屏或上锁,翻页器也没有这套按钮。
\end{itemize}

\subsection*{方案}

\app\ 把 PowerPoint 控制权切成两个人:

\begin{itemize}
  \item \role{导播} —— 后台那台 Windows 机器,装一个 Tauri 桌面应用,负责画面监看、授权管理、和那颗"紧急锁"按钮。
  \item \role{主持人} —— 任何一台手机。扫一个码进网页,不装 App,就能翻页、触发宏、申请黑屏/恢复。
\end{itemize}

主持人按的每一下,都得先经过导播\role{开远控}和他自己\role{ARM}两道闸;导播按下紧急锁会立刻收回所有授权。这套约束的意图很明确:演出出岔子的时候,后台一个按钮就能压住整个场子,而不用先去喊话联络。

\subsection*{为什么这套不一样}

类似的"网页翻页器"工具不少。\app\ 几处不同:

它的传输有两条路。同一栋楼走 LAN 直连(零延迟),跨场地或者场地网络不让你架路由的时候,可以切到架在 CLAB 的中继 —— 主持人手机端不需要改任何东西,只是换个二维码。

它真的对接 PowerPoint COM,不是模拟翻页键。所以幻灯片里那些点按钮触发 VBA 宏的互动模块,比如答题、抽奖、票选,也能直接接进来 —— 这是普通翻页器干不了的事。

授权链是\,\role{开远控 → 紧急锁 → ARM}\,三道闸串起来,任何一道关上主持人都按不动。这不是为了好看,是为了让导播在演出出岔子时不用先去喊话。

\subsection*{对元火动漫社的价值}

几件能直接转化的好处:

主持人手机就是翻页器。LAN 模式下从按下到画面更新大约 30-80\,ms,比一般无线翻页器抗干扰得多 —— 漫展现场的电磁环境本来就乱。

cosplay 大赛公布排名、漫展抽奖、PPT 内嵌答题这些,不再需要专人守着鼠标。主持人自己在台上点,后台只需要监看,人力释放出来去管别的事。

主持人临时换人当场扫码就用。新人 30 秒上手,不需要培训,不需要传翻页器。多段演出节目穿插,每换一个报幕员导播重置一次访问码就行。

真出岔子时,导播按一下紧急锁,主持人那边所有按钮一起失效。这一条听起来简单,但漫展节目交接、设备脱手、主持人下台这些瞬间,有没有这个按钮差别很大。

\subsection*{建议}

如果社团愿意拿一场演出试一下,这边可以这样配合:

\begin{enumerate}
  \item 提供安装包,演出当天到现场陪测一次,有问题当场处置。
  \item 之后按你们用下来的反馈做调整 —— 比如做答题模板、cosplay 评分模板这类常用件。
  \item 事后在白皮书的"致谢"页公开标注合作,就一行字,不是营销文案那种。
\end{enumerate}
