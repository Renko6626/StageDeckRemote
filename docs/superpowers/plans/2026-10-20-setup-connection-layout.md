# Setup 与主持人连接布局实现清单

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 按已确认的第二版样稿收敛 Setup 的信息层级，把 Relay 配置入口放在主持人连接卡片中，同时保留现有功能。

**Architecture:** 沿用现有 Vue 组件、Pinia store 和 Tauri IPC。连接配置从通用设置移至按需打开的面板，继续使用现有保存配置、重启生效机制。业务门控、控制权、Relay 接管和重连策略不变。

**Tech Stack:** Vue 3、Pinia、现有 Tauri / Rust 服务；不增加依赖。

**Spec:** 用户在本次会话确认的布局；`temp/setup-layout-concept/index.html` 为视觉样稿，不是已接入生产服务的功能实现。

## Global Constraints

- 保留原有功能及错误反馈；信息移入详情或面板，不代表删除。
- 不把样稿的示例状态、演示按钮、静态二维码当作真实功能。
- Relay 地址接受 http://、https://、ws://、wss:// 或无前缀主机地址，统一为 ws://，按既有规则校验主机、端口及禁止的路径、查询、账号。
- 不引入 TLS、新 API、配置字段、连接恢复机制或保存后立即连接。
- 保存待生效配置不得改变运行中的连接及二维码；切换 LAN / Relay 二维码不能自动关闭另一条连接。
- 模式切换不得触发远控开关、强制锁、释放控制权；保留冷启动默认 Setup 的行为。
- 尊重已有未提交修改，不覆盖用户文件。
- 页面验证只截图，不自动点击或填写浏览器表单；运行相关已有检查，新永久测试只覆盖实际新增行为或具体回归。
