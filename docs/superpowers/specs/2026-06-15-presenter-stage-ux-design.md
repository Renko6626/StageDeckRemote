# 主持人端台上 UX 改版(Presenter Stage UX)设计

**日期:** 2026-06-15
**状态:** 待审阅
**范围:** 仅主持人前端(`presenter.html` / `presenter.css` / `presenter.js`)。**不动后端、数据契约、三层锁逻辑**。

---

## 1. 背景与目标

主持人端跑在**台上主持人的手机**(扫码进入的浏览器),绝大多数是**竖屏、单手**握持;演出时**主控(MAIN)为主、屏幕同步(SYNC)兜底**。当前版面信息密度偏桌面、最高频的翻页做成「方框+文字」细条且不在拇指热区。

目标:把版面重排成「台上单手控制台」——最高频动作落进屏幕底部拇指弧区、翻页做成大箭头巨钮、宏按钮放大,扫一眼就能下手。保持既有黑白工业「控制台」视觉语言(不重做风格,只重排版面)。

用户已拍板:**布局方案 C(下一页主导)** + **宏按钮双列加大** + **去掉宏名英文小标签**。

## 2. 版面结构(方案 C)

竖屏自顶向下(顶部供扫视、底部供拇指):

1. **状态条(顶,细)** — 品牌 `STAGEDECK·PRESENTER` + 连接点/延迟 + 页码 `PG 03/05`。只读,不放可点主操作。
2. **模式切换** — `主控 MAIN` / `屏幕 SYNC` 分段(沿用现状,激活项反白)。
3. **页码读数** — 大号当前页数字 + `/总数` + `LIVE/IDLE` 标。
4. **页内动作(中段,可滚)** — 宏按钮,**双列**、每个 **min-height 62px / 16px 粗体**、间距 8px。按钮多时此区**纵向滚动**;翻页坞始终钉底不随滚。**去掉**按钮上的英文宏名小标(`data-macro` 仅用于内部,不再显示)。
5. **ARM 安全条(细)** — 位于翻页区正上方。已解锁时低调显示「● 已解锁 · 点此锁定」;**锁定时转为醒目(危险红描边)并禁用其上方所有宏/翻页按钮**。
6. **翻页上行** — `◄ 上一页` | `黑屏` | `恢复` 三格。`上一页`略宽(回退误触代价高于前进,给更多面积)。
7. **下一页巨钮(贴底,全宽)** — 高 80px、**反白(白底黑字)**高亮,全场最高频动作给最强视觉权重与最易达位置。

**SYNC 页**:中段换成 PPT 截图(沿用现有 `snapshot.jpg` 链式刷新与点坐标触发、锁定遮罩),**底部沿用同一套翻页坞**(上一页/黑屏/恢复 + 下一页巨钮),与 MAIN 肌肉记忆一致。

## 3. 组件细节

| 组件 | 规格 |
|---|---|
| 下一页巨钮 | 贴底全宽,高 80px;反白 `#ededee` 底 / `#000` 字;大箭头 `►` 字号 ~34px + 「下一页」~17px;按下短暂反相反馈;`!canTransport()` 时禁用(降透明度)。 |
| 翻页上行 | 三格 grid `1.2fr .9fr .9fr`(上一页略宽);描边样式;`黑屏` 按下短暂红;`恢复` 普通;门控同「下一页」(`canTransport`)。 |
| 宏按钮 | 双列 grid;min-height 62px;16px 粗体中文标签(`label` 优先,空则形状名);点击发 `{shape: data-id}`(沿用 shape-action 触发);`canAct()` 假时禁用。无英文宏名小标。 |
| ARM 安全条 | 细条;解锁态低调、锁定态危险红描边;点按调 `/api/lock`÷`/api/unlock`;`!online || (!allowed && !unlocked)` 时禁用。 |
| 页码读数 | 大数字 `current`(两位补零)+ `/total` + `LIVE/IDLE`(放映中反白)。 |
| 状态条 | 连接点(在线=骨白方点)+ `LLINK/DOWN/TOKEN✗` + 延迟 + 页码。 |

## 4. 视觉与交互

- 沿用既有「控制台」令牌(已提亮的 `--ink-dim/--ink-faint` 等),**不改色板**;巨钮的反白复用激活态语言(同模式切换激活项)。
- 按下反馈:沿用 `:active` 反相;`黑屏` 按下用危险红。
- **锁定态 UX**:锁定时宏区与翻页区按钮全部禁用,ARM 条转醒目;SYNC 页保留「已锁定·点释放控制」遮罩。
- 触控目标:主操作 ≥ 56px 高(下一页 80px、翻页上行/宏按钮 ≥ 62px),满足拇指可达。
- 全部交互逻辑(轮询、401/断线、快照链、三层锁门控 `canAct/canTransport`)**沿用现有 `presenter.js`**,仅随 DOM 结构调整选择器与渲染。

## 5. 响应式 / 平板

phone-first。平板(更宽视口)沿用同一竖屏结构,受 `.frame` 现有 `max-width` 居中约束,巨钮/双列按钮等比放大即可用。**平板的专门优化(如宏按钮 3–4 列、横屏分栏)本次不做**,留作后续单独讨论(用户已同意分开)。

## 6. 影响文件

- `src/presenter/presenter.html` — 重排 DOM:状态条 / 模式切换 / 读数 / 动作区 / ARM 条 / 翻页上行 / 下一页巨钮;SYNC 页底部同构。
- `src/presenter/presenter.css` — 新版面样式(巨钮、翻页上行、双列大按钮、ARM 条);保留 `:root` 令牌。
- `src/presenter/presenter.js` — 适配新结构:`renderActions` 不再写英文宏名小标;事件委托与门控选择器对齐新 DOM;`下一页` 巨钮与翻页上行接 `canTransport`。

## 7. 测试

- **构建完整性:** `presenter.*` 经 `routes.rs` 的 `include_str!` 内嵌,路径不变 → 交叉编译 `cargo xwin build` 仍 0 错误;既有 Rust 测试不受影响(18/18)。
- **静态形状校验:** 主持人页非 TS、不入 vue-tsc;`npm run build` 仍应通过(不涉及该文件)。
- **运行时(用户手机/响应式 devtools 确认):** 竖屏单手下「下一页」贴底易按;宏按钮双列够大、第3页可滚;黑屏/恢复/上一页可用;ARM 锁定/解锁正确禁用上方按钮;SYNC 截图+点坐标+遮罩照常;断线/401/锁定态降级正确。

## 8. 不做(YAGNI / 已知局限)

- 不改后端、`slide_state` 数据、HTTP 接口、三层锁逻辑。
- 不做平板专门版式(见 §5)。
- COM 与手动选窗的分歧仍不在范围(沿用既有约定)。
