# 诊断日志与问题反馈

Windows 源码运行及快照命令见 [本地开发指南](windows-development.md)；本次 GIF 页冻结的已知证据与取证步骤见 [排查交接记录](debugging/2026-10-24-gif-preview.md)。

导播端的“日志”面板保留最近操作，同时自动将常规事件保存到本机。点击“打开日志目录”可以找到文件；实际路径显示在面板中，由系统和 Tauri 的应用日志目录决定。

遇到动画、视频播放时忙碌，或者宏、翻页、网络连接异常时：

1. 勾选“详细诊断”。这个开关只在本次运行有效。
2. 重现一次问题，记下大致时间、页码、操作，以及电脑上是否出现弹窗。
3. 打开日志目录，发送 `diagnostics.jsonl`；如果问题发生在稍早时间，也一并提供 `diagnostics.1.jsonl` 至 `diagnostics.3.jsonl` 中相关文件。

详细模式记录 COM 成员查找和调用的开始、完成、耗时与 HRESULT。调用卡住时，最后的 begin 记录可以帮助定位具体步骤；超时后后台调用若最终结束，仍会留下完成记录。详细模式必须在重现前开启，不能补回之前未记录的步骤。

常规文件还包括应用和系统版本、启动退出、连接状态、操作结果、捕获启停与异常。HTTP 请求只记录路径、方法、状态和耗时；请求编号关联服务端操作，`op_id` 区分同一手机操作的重复请求。详细模式增加成功查询记录，不记录每帧内容。

手机端会将 HTTP 错误、网络错误、请求超时及脚本异常尽力回传到同一份日志，同类错误在 30 秒内抑制重复上报。上报不重试，失败不影响控制操作；完全断网或应用关闭时，未送达的报告不会在恢复后补发。

文件使用 UTF-8 JSONL，每行一条记录，时间为 Unix 毫秒。单文件约 5 MiB，保留当前文件和 3 份历史，总量约 20 MiB。日志写入失败会在面板显示，控制功能继续可用；检查磁盘或目录权限后重启应用。历史文件会轮换覆盖，需要长期保留时请复制到其他目录。

访问码、Relay 密钥和凭据查询参数会过滤；不记录请求体、截图、视频帧或文稿正文。日志仍可能包含窗口标题、形状或宏名称、系统错误与本机目录，分享前可以查看文件内容。

手机诊断接口为 `POST /api/diagnostics`（兼容 `/presenter/api/diagnostics`），沿用 token 认证和现有 Relay 隧道，不开放日志读取。请求字段为 `token`、`client_id`、`kind`（`request`、`connection`、`script`）和最长 2000 字符的 `message`。未授权返回 401，内容不合法返回 400，成功返回 `{"ok":true}`。该返回表示报告已接收；文件写入状态由导播面板展示。
