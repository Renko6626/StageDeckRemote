# ADR-0003：主持人页用原生 JS、由 Axum 直接 serve

- 状态：Accepted（2026-06-14）
- 相关：[architecture.md §3/§4.1](../architecture.md)、[project.md §6.2/§12.2](../project.md)

## 背景

主持人端是现场关键路径：必须任何设备的浏览器扫码即用、零安装、零依赖、加载快、
界面极简防误触。它由导播应用内嵌的 Axum 服务提供。需要决定：这个页面用什么技术、怎样交付。

## 决策

主持人页用**原生 HTML/CSS/JavaScript**（不经构建步骤），由 Axum 通过 `include_str!`
**编译期内嵌**、运行时直接吐出（`GET /presenter` 及 `/presenter/presenter.{css,js}`）。
开发与发布行为一致，无需单独的前端构建产物或静态目录。

## 影响

**正面**
- 主持人页零运行时依赖、体积极小、加载快，最贴合"任何浏览器零安装"。
- 内嵌进二进制，分发时不必随附静态文件；dev/prod 一致。
- 与导播 GUI（Vue + Vite）解耦，互不牵连构建。

**负面 / 代价**
- 不享受 Vue/TS 的类型检查与组件化；逻辑用统一 `render()` 状态机手写约束。
- 文件名与 [project.md §10](../project.md) 列的 `presenter.ts` 略有出入（实际用 `.js`，因为直接交付浏览器、不走构建）。
- 校验只能 `node --check` 语法 + 运行时手测，无法纳入前端类型检查。

## 备选方案

- **作为 Vite 第二入口打包**：能用 TS，但 Axum 需依赖前端构建产物，dev 下手机访问 Axum
  时拿不到已构建资源，链路复杂 —— 否决。
- **导播 GUI 与主持人页共用一个 SPA**：二者界面与信任级别差异大，强行合并得不偿失 —— 否决。
